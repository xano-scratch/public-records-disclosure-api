Public Records Disclosure API

A human clerk and an AI agent call one shared rule to fetch a record. The same versioned policy decides which fields are released, redacted, or withheld, and every read is logged.

What it proves

A record has fields of different sensitivity (public restricted sealed). A versioned policy maps each field's sensitivity and the caller's role to one action: release the value, redact it, or withhold it. That policy lives in one function, and both the human read endpoint and the AI agent endpoint call it. So a clerk asking by hand and an agent asking in plain language get the same, auditable answer. Withholding is computed in the API layer, never with row-level security.

Three roles, one policy

Disclosure agent (AI)

The least-privileged caller. Sees public fields, and nothing sealed. It runs at this fixed clearance even when an admin triggers it.

Records clerk

Sees public and restricted fields; sealed fields are redacted. Opens requests and reads the audit trail.

Records admin

Sees every field, and switches which policy version is active. One switch changes what every caller sees.

Use this template

Clone it, deploy it, and open the link. It seeds itself, so there is data to read right away.

git clone https://github.com/xano-scratch/public-records-disclosure-api
cd public-records-disclosure-api
npm install
npx xanots login          # once per machine
npm run xano:deploy       # deploys the backend, seeds it, prints a live URL

Then open the URL and click "Continue as Disclosure agent (AI)" to see the governance at work.
